# 架构决策记录

## ADR-0001：先实现本地 CLI，再接入外部渠道

### 状态

Accepted

### 决策

第一阶段不接入飞书和微信，先完成本地 CLI、任务编排、受控执行和审计。

### 原因

- 本地执行链路是核心能力。
- 渠道接入不应该掩盖核心任务系统的问题。
- 本地 CLI 更容易调试和测试。
- 后续渠道只需要实现统一的 Adapter 接口。

### 影响

- 第一版不能通过飞书远程控制。
- 可以优先验证代码编写和任务执行能力。
- 未来接入新平台时不需要重写核心逻辑。

## ADR-0002：模型调用必须通过统一接口

### 状态

Accepted

### 决策

业务代码不能直接绑定某一个模型名称。

统一通过类似以下接口调用：

```python
class ModelBackend:
    async def complete(self, request): ...
```

### 原因

- 需要切换 Sol、Luna 或其他模型。
- 需要支持不同任务使用不同模型。
- 方便测试时使用 Mock。
- 避免模型配置散落在业务代码中。

## ADR-0003：高风险操作默认需要审批

### 状态

Accepted

### 决策

以下操作默认需要明确确认：

- 删除文件
- 修改系统配置
- 安装软件
- 执行网络命令
- 访问敏感目录
- 部署服务
- 发送外部消息
- 推送代码
- 操作数据库

### 原因

立凯中枢未来会通过远程平台接收命令，必须防止误操作和提示词注入。

## ADR-0004：任务状态必须持久化

### 状态

Accepted

### 决策

任务不能只存在于内存中，至少保存：

- task_id
- 用户
- 原始请求
- 当前状态
- 开始时间
- 结束时间
- 执行步骤
- 工具调用
- 错误信息
- 审批记录

### 原因

长任务可能中断，远程用户需要查询状态，问题也需要可追溯。
