# 立凯中枢项目计划

## 项目信息

- 项目名称：立凯中枢（Likai Nexus）
- 项目所有者：孙立凯
- 当前阶段：MVP
- 当前状态：DRAFT
- 最后更新：待填写

## 一、项目目标

构建一个运行在家中电脑上的个人全能智能体。

用户可以通过 CLI、飞书或微信发送任务，智能体负责：

1. 理解用户意图。
2. 判断任务类型和风险。
3. 规划执行步骤。
4. 调用本地工具完成任务。
5. 返回执行结果。
6. 保存必要的会话和审计记录。

第一阶段优先支持程序撰写、代码修改、测试运行和项目分析。

## 二、MVP 范围

### 必须实现

- 本地 CLI 入口。
- 任务创建和任务状态管理。
- 模型调用抽象。
- 文件读取和写入。
- 受控命令执行。
- 工作区路径限制。
- 危险操作审批。
- 基础任务日志和审计日志。
- Python 项目的代码修改和测试。
- 任务失败后的错误反馈。

### 第二阶段实现

- 飞书消息接入。
- 飞书用户身份认证。
- 任务执行结果回传。
- 长任务状态查询。
- 任务取消。
- 会话记忆。
- 可复用技能。

### 暂不实现

- 自动删除重要文件。
- 自动部署生产环境。
- 自动发送未经确认的外部消息。
- 自动访问所有本地目录。
- 多用户共享全部权限。
- 无限制的后台自主运行。
- 直接控制微信个人账号。

## 三、总体架构

```text
CLI / 飞书 / 微信
        ↓
Channel Adapter
        ↓
Gateway：认证、限流、消息转换
        ↓
Orchestrator：任务解析、计划和状态管理
        ↓
Safety：权限、审批、路径检查
        ↓
Executor：文件、命令、代码和浏览器操作
        ↓
Workspace / Local Services
        ↓
Storage：任务、会话、审计记录
```

## 四、核心设计原则

1. 默认拒绝，明确允许。
2. 读操作优先，写操作需要确认。
3. 外部渠道不能直接执行本地命令。
4. 所有高风险操作都必须可审计。
5. 所有任务都必须有状态：pending、running、success、failed、cancelled。
6. 任务执行必须具备超时和取消机制。
7. 代码修改必须限制在指定工作区。
8. 模型可以替换，业务代码不能绑定某一个模型。
9. 渠道可以替换，核心任务系统不能依赖某一个平台。
10. 先做可验证的最小版本，再扩展全能能力。

## 五、里程碑

### M0：项目骨架

- 初始化 Python 项目。
- 创建核心目录。
- 创建配置管理。
- 创建基础日志。
- 创建健康检查。
- 完成最小测试。

### M1：本地编程执行

- 实现任务创建。
- 实现文件读取和修改。
- 实现受控终端命令。
- 实现测试运行。
- 实现任务结果汇总。

### M2：安全和审计

- 实现路径白名单。
- 实现危险命令识别。
- 实现审批流程。
- 实现任务审计。
- 实现任务取消和超时。

### M3：飞书接入

- 接收飞书消息。
- 验证用户身份。
- 创建本地任务。
- 异步执行长任务。
- 回传执行结果。

### M4：记忆和技能

- 保存用户偏好。
- 保存项目约定。
- 保存可复用的工作流程。
- 支持技能版本和人工审核。

### M5：微信及其他渠道

- 在安全边界明确后评估微信接入。
- 复用统一 Channel Adapter 接口。
- 不允许渠道层绕过安全审批。

## 六、验收标准

MVP 至少能够完成：

1. 从 CLI 接收一个编程任务。
2. 读取指定项目。
3. 修改指定代码。
4. 执行测试。
5. 返回修改文件和测试结果。
6. 拒绝工作区外的写入。
7. 拦截危险命令。
8. 保存完整任务日志。
9. 在失败后保留可诊断信息。
10. 通过 Reviewer 审查。

## 七、待确认问题

- 最终使用哪一种模型调用方式？
- 本地智能体是否只运行在一台家用电脑？
- 是否需要 Docker 隔离？
- 飞书是否作为第一外部渠道？
- 微信接入是否只做企业微信，还是个人微信？
- 允许智能体访问哪些目录？
- 哪些操作必须人工确认？
- 是否需要支持多个项目工作区？

## 八、当前决策

当前先不实现飞书和微信。

先完成：

```text
本地 CLI
→ 任务编排
→ 受控执行
→ 审批
→ 审计
→ 代码修改和测试
```
