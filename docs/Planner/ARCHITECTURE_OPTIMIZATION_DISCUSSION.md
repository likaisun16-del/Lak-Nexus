## 记录目的

本文只记录当前已经确认的架构优化方向，以及后续仍需讨论的文件架构候选项。
它不是 Implementer 的完整执行计划，也不表示候选项已经获得实施确认。

## 已确认：定制计划 1

实施以下四项优化时，一并把 `tools` 提升为 `likai_nexus` 下的一级包：

1. 建立单一任务执行上下文，使具体 Tool 消费能力和限制，而不是自行解释审查模式。
2. 使用结构化 Tool 结果，明确区分执行状态、模型投影、界面投影和审计投影。
3. 拆分 ToolExecutor 的稳定职责，同时保留唯一执行门面和固定安全顺序。
4. 使用工具无关的通用展示协议，使 CLI 和未来 Channel 不按具体工具名称渲染结果。

目标包位置是：

```text
src/likai_nexus/tools/
```

不采用通用顶级包 `src/tools/`，避免产生脱离 `likai_nexus` 命名空间的独立包和模糊归属。

### 必须保持的职责边界

- Tool 作为一级扩展域，承载工具契约、工具目录和内置工具实现。
- Executor 继续负责安全检查、审批、执行、审计和结果投影的固定生命周期。
- Runtime 负责组装具体工具；Executor 不直接导入具体内置工具。
- Agent Loop 只通过稳定的工具目录和执行接口使用工具。
- 新增普通 Tool 不得要求 Agent Loop、ToolExecutor 或 CLI 增加按工具名称判断的分支。
- 工具继续显式注册；不得通过扫描目录自动开放未经审核的可执行代码。
- 安全顺序保持为：查找、校验、安全检查、审批、执行、脱敏投影、审计终态。

### 非强制目录示意

以下只表达职责，不锁定最终文件名和拆分粒度：

```text
likai_nexus/
├─ tools/
│  ├─ 工具契约与执行上下文
│  ├─ 结构化结果与展示定义
│  ├─ 工具目录
│  └─ builtin/
│     ├─ 文件类工具
│     └─ Shell/进程类工具
├─ executor/
│  ├─ 统一执行门面
│  ├─ 审计生命周期
│  └─ 结果投影
└─ runtime.py
```

## 已确认：定制计划 2

以下四项文件架构优化已经确认可行，与定制计划 1 共同进入后续正式规划范围。
确认的是职责目标和依赖方向，示例目录与具体文件名仍由 Implementer 选择。

### 1. 按归属收敛跨层公共契约

- ToolSpec、ToolCall、结构化 Tool 结果及相关稳定类型归入 Tool 一级域。
- 运行事件作为 Executor、Orchestrator、CLI 和未来 Channel 共用的中立契约，不继续由单一消费层拥有。
- 任务状态、模型消息等类型按真实所有者保留或逐步归位，不为了目录纯洁整体搬迁 schemas。
- 不创建职责不明的 `common`、`shared` 大杂烩包。

### 2. 拆分 CLI 入口与渲染

- CLI 入口负责参数、本地交互、模式选择和 Runtime 调用。
- Console Renderer 独立消费已经安全处理的通用运行事件。
- 新 Tool 的展示不得要求 CLI 增加按工具名称判断的分支。
- 拆分不得改变 `--no-progress`、审批交互和既有退出码语义。

### 3. 保持配置层纯净

- Settings 负责读取、解析、归一化和校验配置。
- Runtime 或等价启动职责负责应用目录准备和组件组装。
- Storage 负责数据库迁移及相关持久化操作。
- 配置对象不再通过延迟导入反向触发 Storage 初始化。

### 4. 拆分超大测试文件并建立 Tool 契约测试

- 测试按 Registry、Executor、展示、安全模式、Runtime 和数据库迁移等稳定职责组织，
  不继续按临时开发阶段堆积到单个超大测试文件。
- 提供新 Tool 可复用的契约测试集合，至少覆盖名称与规格一致性、状态、取消、异常、
  展示隔离、模型投影和审计脱敏。
- 测试重组不得删除既有正常、拒绝、失败、取消和敏感信息回归场景。

## 条件触发：暂不进入当前实施范围

以下内容仍然不是当前定制计划，只有触发条件实际出现后才进入后续讨论：

### 候选 E：按需求升级存储与迁移目录

当数据库继续增加结构迁移、后台恢复或第二种存储实现时，再讨论 SQLite 实现目录和有序迁移目录。
当前不为尚未出现的存储规模预建复杂 Repository 或 Unit of Work 层。

### 候选 F：按真实复用提取进程运行能力

当出现第二个进程型工具时，再从 Bash 工具域提取环境清理、输出排空、超时、取消和进程树终止。
在此之前不创建没有第二个调用方的通用进程框架。

### 候选 G：第二 Channel 前建立应用级任务门面

接入飞书、微信或 HTTP 前，可增加渠道无关的任务提交、查询、取消和事件订阅边界。
在只有本地一次性 CLI 时，不提前创建空的 application 层。

## 反锚定说明

- 已确认的是 Tool 一级域、依赖方向、公共契约和安全顺序，不是具体文件名。
- 定制计划 2 锁定职责归属和兼容结果，不强制新增顶层包数量或内部类名。
- Implementer 可以在保持行为和安全契约的前提下调整内部拆分。
- 条件触发项必须经后续讨论确认后才能进入实施计划。
- 不创建空目录、空转发类或只为“看起来分层”存在的抽象。
